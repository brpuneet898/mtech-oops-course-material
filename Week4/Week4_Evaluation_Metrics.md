# Evaluation Criteria (Total: 100 Marks)

| Component                         | Marks | Description |
|----------------------------------|-------|-------------|
| UML from initial code            | 15    | Clarity, correctness of class relationships and structure before refactor |
| SOLID refactoring                | 20    | Effective application of SRP, OCP, LSP, DIP, and/or ISP in code |
| UML after refactor               | 10    | Correctly reflects improved design; highlights changes |
| TDD test cycle                   | 20    | Evidence of Red-Green-Refactor steps; meaningful test coverage |
| Code quality & structure         | 15    | Clean, modular, well-structured code that adheres to OOP practices |
| Reflection answers               | 10    | Depth and clarity in reflecting on SOLID, UML, and TDD challenges |
| Completion & submission quality  | 10    | All deliverables submitted, named correctly, and clearly organized |

---

## Notes for TAs

- Use inline comments or annotations in the submitted notebook or code if possible.
- Partial marks can be given if the intent is clear but implementation is incomplete.
- Use reflection questions to verify conceptual understanding, especially of tricky principles like LSP or DIP.
