# Week 9 Lab Evaluation Metrics

## Evaluation Rubric

| Section | Task Description | Max Marks | Evaluation Criteria |
|--------|------------------|-----------|----------------------|
| **1.1** | Binary Search Tree Implementation | 15 | Insert/Delete/Search correctness, inorder traversal, balance check |
| **1.2** | AVL Tree (Self-Balancing BST) | 15 | Correct rotations (LL, RR, LR, RL), height updates, in-order output |
| **2.1** | MinHeap & MaxHeap | 15 | Bubble-up/heapify logic, insert & extract correctness, heapify method |
| **2.2** | Priority Queue with Jobs | 15 | Proper ordering using priority & timestamp, enqueue/dequeue/peek |
| **3.1** | Heap-Based Job Scheduler (Core Project) | 25 | Priority-driven execution, time tracking, wait time, log tracking |
| **4.1** | Comparative Analysis (BST vs AVL vs Heap) | 10 | Technical depth, correct time complexity, clarity, practical insight |
| **Stretch** | Real-time Job Re-prioritization (Optional) | +5 bonus | Dynamic priority changes handled efficiently in scheduler |
| **Code Quality** | Structure, readability, comments, edge case handling | 5 | Modular, well-commented, good variable naming |
| **Test Cases** | Additional user-defined test cases for custom scenarios | 5 | Thorough and diverse test inputs, edge case coverage |

## Notes

- **Partial credit** should be awarded for logical structure even if output has minor bugs.
- **Auto-evaluation** may cover:
  - BST in-order correctness
  - AVL balance conditions after random insertions
  - Job scheduler execution trace validation
- **Manual evaluation** is required for:
  - Rotation logic
  - Heap operations if implemented from scratch
  - Reasoning quality in markdown responses

## Weightage Approach

| Category                | Weight (%) |
|-------------------------|------------|
| Implementation Correctness | 60% |
| Real-world Mapping / Use-Case | 20% |
| Code Style & Design      | 10% |
| Explanation / Analysis   | 10% |
